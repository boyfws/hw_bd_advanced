# Автоматизированное развертывание Apache Hive

В этой работе рассматривается развертывание Apache Hive с возможностью одновременного подключения нескольких клиентов. Для хранения метаданных используется отдельный Hive Metastore с PostgreSQL, а доступ к Hive осуществляется через HiveServer2. Такой подход позволяет не использовать embedded-режим.

Также подготовлена автоматизированная загрузка CSV-файла в партиционированную таблицу Hive. Развертывание и выполнение скриптов запускаются через GitHub Actions.

## Состав кластера

Для работы используется кластер Hadoop, развернутый в предыдущих домашних заданиях.

1. `team-14-nn`, `10.14.0.11` – NameNode и Secondary NameNode.
2. `team-14-en`, `10.14.0.10` – edge-нода, DataNode и HiveServer2.
3. `team-14-00`, `10.14.0.12` – DataNode, NodeManager, Hive Metastore и PostgreSQL.
4. `team-14-01`, `10.14.0.13` – DataNode.

Используются Hadoop 3.5.0, Hive 4.1.0 и PostgreSQL 16. Для выполнения запросов дополнительно подготовлен Apache Tez 0.10.5.

Hive установлен в `$HOME/apache-hive-4.1.0-bin`, Hadoop – в `$HOME/hadoop-3.5.0`.

## Как устроено развертывание

Основной сценарий находится в `.github/workflows/deploy-hive.yml`. Он запускается вручную через GitHub Actions.

При запуске GitHub Actions подключается к edge-ноде по SSH, передает файл `hw_3/deploy.sh` и выполняет его на сервере.

Скрипт проверяет окружение, наличие необходимых компонентов, доступность PostgreSQL и Hive Metastore, после чего настраивает HiveServer2.

Hive Metastore использует PostgreSQL на узле `team-14-00` и работает на порту `9083`. HiveServer2 запускается на edge-ноде и принимает подключения на `127.0.0.1:10000`.

Текущий сценарий использует предварительно подготовленный кластер Hadoop и установленные компоненты. Полная установка на пустых серверах одним запуском не проверялась.

## Подключение нескольких клиентов

Для подключения к HiveServer2 используется Beeline:

```bash
beeline -u "jdbc:hive2://127.0.0.1:10000/default"
```

Поскольку используется отдельный HiveServer2, несколько клиентов могут подключаться к одному серверу независимо друг от друга.

Для проверки был подготовлен сценарий `.github/workflows/check-hiveserver2-log.yml`, который одновременно запускает два клиента Beeline. Каждый выполняет команду `SHOW DATABASES;`.

Проверка завершилась успешно в GitHub Actions, запуск №14.

## Загрузка данных в Hive

В качестве исходных данных используется файл `hw_3/transactions.csv`, содержащий 12 записей о транзакциях.

Сначала CSV загружается в HDFS по пути `/user/team/hw3/raw_transactions/`.

Для загрузки используются две таблицы. `transactions_raw` читает исходный CSV как текстовый файл, а `transactions` предназначена для хранения обработанных данных в формате Parquet с партиционированием по `transaction_year`.

Команды создания таблиц находятся в `hw_3/create_table.sql`, а загрузки данных – в `hw_3/load_data.sql`.

Для переноса данных предусмотрена команда:

```sql
INSERT OVERWRITE TABLE transactions
PARTITION (transaction_year)
SELECT
    transaction_id,
    customer_id,
    amount,
    category,
    transaction_year
FROM transactions_raw
WHERE transaction_id IS NOT NULL;
```

Автоматизированный запуск предусмотрен в `.github/workflows/load-hive-data.yml`.

## Проверка результата

После успешной загрузки необходимо проверить количество записей и созданные партиции:

```sql
USE hw3;

SELECT COUNT(*) FROM transactions;

SHOW PARTITIONS transactions;

SELECT transaction_year, COUNT(*)
FROM transactions
GROUP BY transaction_year
ORDER BY transaction_year;
```

Ожидаемый результат - 12 записей и три партиции: 2024, 2025 и 2026.

На момент подготовки инструкции выполнение `INSERT OVERWRITE` завершалось ошибкой вычислительного задания в YARN. Создание таблиц и загрузка исходного файла в HDFS выполнялись успешно, но заполнение партиций не подтверждено.

## Запуск через GitHub Actions

Для запуска необходимо открыть публичный репозиторий, перейти во вкладку **Actions**, выбрать нужный сценарий и нажать **Run workflow** для ветки `master`.

Основные сценарии:

1. `deploy-hive.yml` – настройка и запуск HiveServer2.
2. `setup-tez.yml` – подготовка Tez и исходных данных.
3. `load-hive-data.yml` – создание таблиц и попытка загрузки данных.
4. `check-hiveserver2-log.yml` – проверка двух одновременных клиентов.

Для подключения используются GitHub Secrets `SSH_PRIVATE`, `KNOWN_HOSTS` и `HIVE_DB_PASSWORD`. Значения секретов не хранятся в открытом коде.

## Итог

В работе развернут Apache Hive с отдельным Hive Metastore и HiveServer2. Подключение через Beeline работает, возможность одновременного использования Hive двумя клиентами проверена.
Подготовлены скрипты автоматизированного развертывания, загрузка исходных данных в HDFS и SQL-команды для заполнения партиционированной таблицы.
Ограничением остается ошибка выполнения вычислительного задания при записи данных в таблицу Hive. Поэтому автоматизированная загрузка реализована в виде сценария, но ее успешное выполнение пока не подтверждено.
